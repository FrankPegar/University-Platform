# v1.1 editing verification

Verified September 19, 2026 against the existing Coursepoint repository, local frontend/Express backend, and configured Supabase project.

## Implemented

| Editor | Editable fields | Restrictions |
| --- | --- | --- |
| Question | Title, Markdown body, tags | Question author only. Department is prefilled and read-only because the PATCH validator does not support changing it. |
| Answer | Markdown body | Answer author only. Acceptance, votes and comments are preserved. |
| Profile | Full name, department, course, year level (1–8) | Current student only. Student ID is read-only. Changing department clears the course; only courses fetched for the selected department are available. |

All editors provide Save/Cancel, validation, saving state, duplicate-submission protection, and backend/network error feedback while retaining drafts. Cancel sends no PATCH. Saved question/answer content updates in place through the existing Markdown renderer. Profile saves update the auth context from the canonical PATCH response so the header, department panel, and Home feed use the saved profile.

Existing API/auth logic and server ownership checks are reused. Editable payloads do not contain `author_id`, `user_id`, or `student_id`.

## Rerunning

With the frontend on port 5173, backend on 4000, and a separate Chrome profile exposing local debugging port 9223:

```sh
node --test server/test/*.test.js
npm --prefix client run build
node client/test/editing.browser.mjs
node client/test/acceptance.browser.mjs
node client/test/live-mvp.browser.mjs
node client/test/live-resilience.browser.mjs
node client/test/live-editing.browser.mjs
```

Run browser suites sequentially. Mock suites use `http://127.0.0.1:5173`; live suites use `http://localhost:5173`. Live suites read `COURSEPOINT_TEST_ACCOUNTS` (default `/private/tmp/coursepoint-phase5f-accounts.json`), use the existing dedicated account fixtures, and write real test content. The live editing suite uses the question/answer artifact produced by the live MVP suite and restores its starting fixture values on a successful run. An interrupted live run can leave test edits in place.

## Remaining limitations

- Question department and student ID are intentionally read-only under the current API contract.
- Existing question text/tag updates involve multiple database operations; a later failure can follow an earlier committed change. The UI reports failure and retains the draft for retry. This phase fixes the ignored tag-deletion error without adding a database transaction/migration.
- Existing session-expiry and two-write acceptance limitations documented in `mvp-verification.md` remain unchanged.
- Mobile checks used Chrome viewport emulation, not physical devices.

No comment/admin editing, history, AI editing, notifications, or other features were added.
