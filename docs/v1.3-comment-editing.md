# v1.3 — Comment editing and deletion

Implemented and verified October 5, 2026. Existing MVP, v1.1 editing, and v1.2 profile pictures are preserved.

## Behavior and authorization

- Question and answer comments show compact Edit/Delete actions only to their author.
- Edit prefills the plain-text body. Save validates 1–1000 characters after trimming, displays pending/errors, and replaces the comment with the canonical API response. Cancel discards the draft without a request.
- Delete requires inline confirmation. Cancel sends no request. A successful delete removes the comment and updates the count immediately. Failures retain the comment and confirmation for retry; a retry receiving 404 reconciles an already-deleted comment.
- Save/delete requests are protected against duplicate clicks. A response arriving after a thread or session change cannot update the new thread.
- Comment text remains escaped plain text, including Markdown punctuation and HTML-like text. Existing author names, dates, and profile pictures remain visible.
- New authenticated `PATCH /api/comments/:id` accepts only `body`. Its UUID/body validator strips unrecognized fields, including ownership and parent IDs. The service checks ownership using the verified token's user ID and constrains the mutation by both comment ID and author ID.
- Existing `DELETE /api/comments/:id` keeps its author-only authorization and now also constrains the delete query by verified author ID. Question/answer ownership gives no rights over another student's comment.
- No database migration, dependency, or Supabase setup is required.

## Remaining limitations

- Simultaneous edits in separate tabs use the existing last-write-wins behavior; there is no revision history or conflict merge.
- Network failure after a committed save may require retry or refresh to see the server result. A delete retry handles an already-deleted comment as removed.
- Mobile verification used viewport emulation, not a physical device.

No moderation/admin deletion, history, nested comments, notifications, or other post-v1.3 features were added.
